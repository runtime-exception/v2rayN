# macOS 客户端原生化与 Liquid Glass 界面重构计划

## 实施状态（2026-09-18）

- 已完成 macOS 专用设计令牌、浅色/深色语义资源与平台限定样式。
- 已完成 AppKit `NSVisualEffectView` 窗口背景、透明度降级及辅助功能外观适配。
- 已完成主窗口原生标题栏、source-list 侧边栏、玻璃工具栏/状态条和 600/760/1000 px 响应式布局。
- 已完成节点、日志、代理、连接、设置、编辑窗口和消息框的统一表面与控件样式接入。
- 保留原 ViewModel、命令、快捷键、菜单、配置结构和三种主区域布局；macOS 窄窗口只临时切换单页布局，不覆盖用户偏好。
- 已通过全部相关 AXAML 的 XML 结构校验及 `git diff --check`。
- 已使用 .NET SDK 10.0.401 完成 macOS arm64 Release 构建以及 arm64/x64 自包含发布；`ServiceLib.Tests` 121 项全部通过。
- 已生成 arm64/x64 DMG，完成 plist、磁盘映像校验及主程序/core 二进制架构核对；macOS 真机视觉矩阵仍需人工验收。

## 总体方案

- 仅对 macOS 启用新界面；Windows/Linux 继续使用现有布局与样式。
- 覆盖主窗口、节点、日志、代理、连接、设置、编辑窗口、弹窗及状态栏。
- 保留全部 ViewModel、命令、快捷键、右键菜单、托盘行为、配置格式和三种主区域布局。
- 采用“AppKit 原生背景材质 + Avalonia 语义化玻璃表面”混合实现，不增加第三方依赖。
- 继续支持 macOS 13.6，不因视觉重构提高最低系统版本。

## 主要改动

### 1. macOS 视觉基础设施

- 新增仅在 macOS 加载的资源和样式，统一以下设计令牌：
  - 4/8/12/16/24 间距体系。
  - 控件 8、卡片 12、浮层 16 的圆角层级。
  - 系统蓝主色、语义化成功/警告/错误色。
  - 主文本、次级文本、分隔线、内容背景、玻璃背景等浅色/深色资源。
  - 轻量边缘高光与低强度阴影，避免厚重悬浮效果。
- 使用系统默认字体并建立标题、正文、说明、等宽数据四级排版；现有字体、字号设置继续生效，但改为更新语义化字号资源，不再给所有控件强制相同字号。
- 保留 `FollowSystem`、`Light`、`Dark`、`Aquatic`、`Desert`、`Dusk`、`NightSky`，后四者沿用当前 Semi 主题主色并套用新的表面层级。

### 2. 原生 Liquid Glass 材质

- 扩展现有 macOS Objective-C 互操作，在窗口加载后向 `NSWindow` 注入单个底层 `NSVisualEffectView`：
  - 使用适合窗口背景的系统 Material。
  - `behindWindow` 混合模式。
  - 跟随窗口激活状态。
  - Avalonia 根背景透明，内容区域使用可读性更高的语义化表面。
- `WindowBase` 统一负责挂载、刷新和释放材质，使所有设置及编辑窗口自动获得一致效果。
- 侧边栏、工具栏、底部状态条和弹窗使用半透明玻璃表面；节点表格、日志和长表单使用标准内容材质，避免玻璃效果泛滥。该分层符合 Apple 将 Liquid Glass 限制在导航和功能层的建议。[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)
- 当原生互操作不可用或初始化失败时，自动使用实色背景，不能影响窗口启动或业务操作。
- 监听系统“降低透明度”“增强对比度”“减少动态效果”设置：降低透明度时完全切换为不透明表面，减少动态效果时关闭位移和缩放动画。[Apple Accessibility](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducetransparency)
- 不依赖 Avalonia 的 `Blur/AcrylicBlur`，因为当前 Avalonia 在 macOS 上只保证 `Transparent`，真实模糊需由 AppKit 提供。[Avalonia Window Management](https://docs.avaloniaui.net/docs/app-development/window-management)

### 3. 主窗口与响应式布局

- 保留 macOS 系统交通灯，内容延伸至标题栏，形成统一的玻璃工具栏。
- 左侧增加 source-list 风格导航，包含节点、日志、代理、连接四个现有功能入口，并显示当前活动节点和连接状态。
- 主内容区域：
  - 节点页保留高信息密度表格及全部列排序、拖动、宽度保存、快捷键和右键操作。
  - 去除密集的全网格线，改用行分隔、悬停高亮、选中背景和活动节点状态胶囊。
  - 分组、搜索、延迟测试和常用操作集中到内容工具栏；低频操作继续放在原有菜单或更多菜单中。
- 底部状态栏改为玻璃控制条，保留运行节点、监听端口、TUN、系统代理、路由、上下行速度等全部信息和操作。
- 保留 `Horizontal`、`Vertical`、`Tab` 三种布局及已保存的分割尺寸：
  - ≥1000 px：展开侧边栏。
  - 760–999 px：收缩为图标栏并通过 Tooltip 显示名称。
  - 600–759 px：暂时使用工具栏导航和单页展示，不修改用户保存的布局偏好；窗口变宽后恢复原布局。
- 常用按钮保持单击可达，所有原有菜单功能仍可访问，不以仅依赖颜色的方式表达状态。

### 4. 完整客户端统一

- 设置窗口改为左侧分类导航、右侧滚动内容区；原有字段按“网络入口、核心、系统代理、TUN、界面、更新”等现有含义组织成标准设置卡片。
- 添加节点、订阅、DNS、路由及规则编辑窗口统一采用：
  - 清晰的窗口标题和说明。
  - 对齐的标签与输入区。
  - 分组卡片与固定底部操作区。
  - 主按钮、普通按钮、危险操作的明确层级。
- Clash 代理页使用 source-list + 自适应节点卡片；连接页沿用数据表格但统一搜索、刷新和关闭操作区。
- 日志页使用标准工具栏和等宽内容区，保留自动刷新、滚动到底、过滤、复制及清空能力。
- `DialogHost`、确认框、更新检查、备份恢复和二维码等浮层统一为 sheet 风格：半透明遮罩、16 px 圆角、内容区与操作区分层。
- 现有 Semi 图标继续使用并统一为 16/18 px 单色图标，不引入新的图标依赖。

## 交互与兼容性

- 悬停颜色过渡约 120 ms，按压反馈约 80 ms，页面切换使用约 160 ms 淡入淡出，弹窗使用约 180 ms 淡入及轻微缩放；不加入弹跳、持续脉冲或装饰性动画。
- 完善 hover、pressed、selected、disabled、keyboard-focus 和 inactive-window 状态。
- macOS 显示 `⌘` 风格快捷键，同时保留当前 `Ctrl` 别名和所有现有命令。
- 不修改 `ServiceLib` 业务接口、配置 JSON 结构、主题枚举、ViewModel 命令或持久化字段。
- 新增内容仅为内部 macOS 外观控制器、平台样式资源以及 `macos/compact/narrow` 运行时样式类，不公开新的业务 API。
- Windows/Linux 不加载 macOS 材质和样式，原有窗口及交互路径保持不变。

- 构建与回归：
  - 构建 `v2rayN.Desktop` 和完整解决方案。
  - 执行 `ServiceLib.Tests`。
  - 分别完成 macOS arm64、x64 发布与现有打包流程。
  - 执行 `git diff --check`，确认无配置格式和无关业务代码变动。
- 功能回归逐项覆盖：节点增删改、导入导出、移动、测速、订阅更新、系统代理、路由、TUN、Clash、日志、主题、语言、托盘、窗口隐藏/恢复、Dock 激活及全部弹窗。
- 视觉矩阵覆盖：
  - 系统浅色、系统深色、强制浅色、强制深色及现有扩展主题。
  - 600、760、1000、1200、1440 px 窗口宽度。
  - 活动/非活动窗口、降低透明度、增强对比度、减少动态效果。
- 可访问性检查：完整键盘导航、可见焦点、VoiceOver 名称、文本缩放、状态不只依赖颜色、浅色和深色对比度。
- 验收标准：
  - 所有现有功能和设置均可从新界面访问，命令参数及保存结果不变。
  - 调整窗口大小时无控件重叠、截断或不可恢复的隐藏。
  - 系统外观和辅助功能设置变化后界面即时正确降级。
  - AppKit 材质失败时仍能正常启动并显示完整的不透明界面。
  - Windows/Linux 无 macOS 专用视觉或行为回归。
